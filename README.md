## 一、项目解决什么问题

### 1.1 现实痛点

我国老年慢病人群的用药依从性长期偏低，漏服、错服、过期药品堆积、购药不便，共同构成家庭用药安全的灰色地带：

| 问题 | 关键数据（引自项目策划书） |
|---|---|
| **漏服高发** | 60 岁以上老年人慢性病患病率 **75%**，其中 **80.60%** 每日需服用 3 种以上药物；用药依从性良好者仅 **36.86%**，**63.14%** 存在不同程度的不依从，其中 **77.1%** 源于「忘记服药」 |
| **说明书看不懂** | 仅 **22.92%** 的老年患者能完全看懂药品说明书，**17.89%** 明确表示看不懂 |
| **数字鸿沟** | 老年慢病患者中 **61.97%** 为初中及以下学历；现有智能药盒多依赖手机 APP 与 WiFi 配网，学习成本高 |
| **价格门槛** | **83.04%** 的老年患者月收入低于 5000 元；进口产品 500–1000 美元，国产智能产品 200–400 元，中间价格带的适老化产品缺位 |
| **子女远程焦虑** | 约 **1.6 亿** 老年人独立居住，异地子女无法实时掌握父母服药情况 |

### 1.2 本项目的解法

用**物理交互替代触屏交互**，让老人零学习成本地完成服药，让子女零操作地远程守护：

- **对老人**：到点自动「亮灯 + 响铃 + 语音播报药名剂量」，拿药只需开盖，无需操作任何屏幕；离线语音播报，**不联网也能正常提醒**
- **对子女**：微信小程序实时查看父母服药记录、依从性评分与库存预警，漏服自动推送提醒
- **对断网场景**：设备端本地判定漏服并缓存记录，联网后自动补发，**断网不丢数据**

## 二、主要功能

### 2.1 硬件端（Orange Pi 4 Pro）

| 功能 | 实现方式 | 状态 |
|---|---|---|
| 到点提醒 | `scheduler.py` 按云端计划展开当日时点，到点触发 | ✅ 已实现 |
| 三重感官提醒 | 分仓 LED 指示灯 + 有源蜂鸣器（每 5 秒重复）+ 离线语音播报 | ✅ 已实现 |
| 取药检测 | 霍尔传感器检测开盖（**开盖即算取药**，不强制按键）+ 确认大按键双通道 | ✅ 已实现 |
| 漏服判定 | 提醒 **120 秒**内无确认 → 本地判定漏服并上报 | ✅ 已实现 |
| 视觉二次确认 | OpenCV 轮廓法清点药片，取药前后比对（面积降幅 >8% 判为已取走） | ✅ 已实现（可选，`--vision`） |
| 离线语音 | 优先播放 `voices/bay*.wav` 预录语音，无录音时用 `espeak-ng` 合成 | ✅ 已实现 |
| 断网续传 | 上报失败写入 `pending.json` 本地队列（上限 200 条），联网后补发 | ✅ 已实现 |
| 计划同步 | 每 **10 分钟**拉取云端用药计划；失败则沿用旧计划，不清空 | ✅ 已实现 |
| 设备心跳 | 每 **3 分钟**上报在线状态与电量 | ⚠️ 见 [六、已知问题](#六已知问题) |
| 无元件开发 | `MockHardware` 模拟模式，打印代替点灯/响铃/播报，键盘模拟开盖 | ✅ 已实现 |

### 2.2 云平台与小程序（微信云开发 Serverless）

9 个云函数 + 5 个小程序页面：

| 模块 | 职责 |
|---|---|
| `login` | 登录 / 用户初始化 |
| `elder` | 老人档案 CRUD |
| `device` | 药盒绑定、解绑、药仓配置、心跳 |
| `plan` | 用药计划 CRUD（同一药仓禁止并存两个生效计划） |
| `record` | 服药记录查询、**设备事件上报**、漏服补齐 |
| `dashboard` | 首页看板聚合（今日计划、今日记录、依从性、预警、设备状态） |
| `analytics` | 依从性评分、库存预警扫描、预警列表 |
| `notify` | 订阅消息推送（含每 5 分钟定时触发器） |
| `init` | 数据库集合初始化（幂等） |

**小程序页面**：守护（首页看板）、记录、用药（计划管理）、药盒（设备管理）、我的

**核心算法**

- **依从性评分**：`得分 = (按时×1.0 + 提前×0.8 + 延迟×0.5 + 漏服×0) / 应服总次数 × 100`
  - `on_time` 计划时间 ±30 分钟；`early` 提前 30 分钟以上；`late` 延迟补服；`missed` 当天无记录
  - 分级：`≥90 优秀` / `75–89 良好` / `60–74 一般` / `<60 需关注`
- **库存预警**：`剩余天数 = stock / dailyConsumption`，**≤7 天**生成 `low_stock` 预警（≤3 天为 `high` 级），同一计划 24 小时内不重复告警
- **时区安全**：云函数运行在 UTC 环境，所有日期与「当日分钟数」统一换算到北京时间（UTC+8）后再比对，避免「早上 8 点的药被判成下午漏服」

> 计划书中规划的 **NFC 被动读取**、**O2O 一键购药（美团买药 / 京东药急送 API）**、**药师在线咨询** 尚未实现。其中 O2O 开放 API 不对个人开发者开放，需企业资质，当前版本「去补药」做的是复制药名。

## 三、安装方法

### 3.1 环境要求

| 组件 | 要求 | 说明 |
|---|---|---|
| 硬件端运行环境 | Orange Pi 4 Pro + Armbian（Debian 系） | 本地开发用 Windows / macOS / Linux 亦可（模拟模式） |
| Python | **≥ 3.8**（实测 3.12.9） | 业务代码几乎只用标准库 |
| Node.js | 用于本地跑云函数测试（实测 v24.21.0） | 不需要 npm install |
| 微信开发者工具 | 稳定版 | 部署云函数与小程序 |

### 3.2 硬件端安装

```bash
sudo apt update && sudo apt install -y \
    python3-opencv \
    python3-numpy \
    gpiod \
    python3-libgpiod \
    espeak-ng \
    alsa-utils \
    v4l-utils
```

各包用途：

- `python3-opencv` / `python3-numpy` —— 药片计数、摄像头取图
- `gpiod` / `python3-libgpiod` —— GPIO 控制与引脚编号查询
- `espeak-ng` / `alsa-utils` —— 离线语音合成与播放
- `v4l-utils` —— 查看摄像头支持格式
- 可选：`ffmpeg`（`cam.py` 的 MJPEG 推流）

> ⚠️ **故意不用 pip**。ARM 架构上 pip 经常没有预编译包，会现场编译几十分钟且容易失败；用 apt 装 Debian 打包好的 aarch64 版本只需几秒。详见 `硬件端/requirements.txt`。

**上传代码到板子**（在你自己的电脑上执行）：

```bash
scp -r 硬件端/ orangepi@<板子IP>:~/
```

**环境自检**（会逐项检查 Python / OpenCV / GPIO / 摄像头 / 音频 / 云端配置）：

```bash
cd ~/硬件端
python3 main.py --selftest
```

### 3.3 云平台安装

1. **注册小程序拿 AppID**：访问 <https://mp.weixin.qq.com/> 注册个人小程序（免费）。
   ⚠️ 一定要正式小程序，**测试号不支持云开发**。
   > 本仓库 `智药云联云平台/project.config.json` 里的 `appid` 是**占位值** `wx0000000000000000`，
   > 请替换成你自己的 AppID（微信开发者工具导入项目时也会提示你填写）。
2. **导入项目**：微信开发者工具 → 导入项目 → 选择 `智药云联云平台/` 目录 → 后端服务选「微信云开发」。
3. **开通云开发环境**：工具顶部「云开发」→ 开通（按量付费，用免费额度）→ 复制**环境 ID**。
4. **填环境 ID**：打开 `miniprogram/app.js`，把 `YOUR_ENV_ID` 换成你的环境 ID。
5. **上传云函数**：右键 `cloudfunctions/` 下每个文件夹 → 「上传并部署：云端安装依赖」，共 9 个。
6. **初始化数据库**：云开发控制台 → 云函数 → `init` → 云端测试，参数填 `{}` → 运行，返回 `code: 0` 即成功。
7. **设置数据库权限**：控制台 → 数据库 → 每个集合 → 权限设为「**所有用户不可读写**」。
   服药数据属个人健康信息，受《个人信息保护法》约束；所有读写均经云函数完成，客户端从不直连数据库。
8. **配置订阅消息**（可选，不配则收不到推送）：小程序后台申请「用药/服药」类模板 → 把**模板 ID** 填入 `miniprogram/utils/subscribe.js` 的 `TEMPLATE_IDS` 和 `cloudfunctions/notify/index.js` 的 `TEMPLATE_ID`，并按实际字段名调整 `buildTemplateData()`。

## 四、使用方法

### 4.1 硬件端

**模拟模式**（元件未到货也能跑完整流程，默认模式）：

```bash
python3 main.py
```

运行后按键盘：

```
0~5   模拟第 N 号仓被打开取药（2 秒后自动合盖）
b     模拟按下确认键
q     退出
```

**真实硬件模式**：

```bash
python3 main.py --real
# 或
ZHIHYAO_MOCK=0 python3 main.py
```

**常用参数**：

```bash
python3 main.py --selftest        # 只做环境自检，不进主循环
python3 main.py --test-bay 0      # 启动 2 秒后对 1 号仓演练一次完整提醒（答辩演示用）
python3 main.py --vision          # 启用摄像头视觉确认
python3 main.py --vision-debug    # 启用视觉并把调试图像存到 debug_shots/
```

**接真实硬件前必读**：

⚠️ **Orange Pi 4 Pro 的 40-pin 定义与树莓派不同，接错 5V 会直接烧板子。**

1. 去香橙派官网下载 **Orange Pi 4 Pro 引脚定义图**
2. `python3 tools/test_gpio.py list` 打印所有 GPIO 的 line number
3. 对照图纸，把 `config.py` 里 `LED_PINS` / `BUZZER_PIN` / `BUTTON_PIN` / `LID_PINS` 的**占位编号**换成真实 line number
4. **先验证单个引脚再继续接线**：

```bash
python3 tools/test_gpio.py blink 17   # 接好 LED + 限流电阻后试闪
python3 tools/test_gpio.py watch 27   # 接好霍尔传感器后监视
python3 tools/test_gpio.py scan       # 依次点亮所有药仓 LED
```

**摄像头调参**：

```bash
python3 tools/test_camera.py shot      # 先看能不能拍清
python3 tools/test_camera.py tune      # 交互式调参
python3 tools/test_camera.py compare   # 模拟取药前后的比对
```

### 4.2 云平台

1. 微信开发者工具点「编译」，扫码预览。
2. **没有真实药盒也能测**：`device` 云函数 `bind` 动作支持绑定测试设备（`bindCode` 随便填），再用 `record` 的 `report` 动作上报事件。
3. **本地测试云函数逻辑**（不联网、不消耗云开发额度）：

```bash
cd 智药云联云平台
node tests/run.js
```

原理：`tests/wx-server-sdk-stub.js` 用内存对象实现了云数据库核心接口，`tests/run.js` 把 `require('wx-server-sdk')` 重定向到该替身，然后直接调用云函数的 `exports.main()`。

### 4.3 运行测试

```bash

cd 硬件端 && python3 test_logic.py
```

### 5.3 设备上报：请求与响应

**请求**（硬件端 `cloud.report_event()` 实际发出的内容）：

```http

  "deviceId": "BOX-TEST01",
  "bayIndex": 0,
  "eventType": "taken",
```

`eventType` 取值：

| 值 | 含义 |
|---|---|
| `taken` | 传感器检测到取药 |

| `lid_open` | 仅开盖，**不单独计为服药**，只作过程日志 |

```json

  "data": {
```

`status` 由「实际时间 − 计划时间」的差值判定：`|diff| ≤ 30` → `on_time`，`diff > 30` → `late`，`diff < -30` → `early`。

### 5.4 云函数调用示例（小程序端）

所有云函数统一返回 `{ code, msg, data }`，`code === 0` 表示成功；除 `login` 外均通过 `event.action` 区分动作。

```js
// 依从性评分（对应策划书 2.3.2 节）
wx.cloud.callFunction({
  name: 'analytics',
  data: { action: 'adherence', days: 7 }
})
// → {
//     code: 0,
//     data: {
//       score: 70,
//       level: { min: 60, label: '一般', color: '#E8A33D' },
//       days: 7, startDate: '2026-10-07', endDate: '2026-10-13',
//       totalCount: 5,
//       byStatus: { on_time: 3, early: 0, late: 1, missed: 1 },
//       trend: [ { date: '2026-10-11', total: 2, weighted: 1.5, missed: 0, score: 75 } ],
//       byMedicine: [ { name: '苯磺酸氨氯地平片', total: 5, missed: 1, score: 70 } ]
//     }
//   }
//
//   计分：3×1.0（按时） + 1×0.5（延迟） + 1×0（漏服） = 3.5
//         3.5 / 5 × 100 = 70 分 → 「一般」

// 首页看板
wx.cloud.callFunction({ name: 'dashboard', data: { action: 'summary' } })
// → { code: 0, data: { todayPlans, todayRecords, adherence, alerts, device } }

// 绑定药盒（无硬件时 bindCode 随便填，便于先跑通流程）
```

## 六、已知问题

以下问题在**阅读源码并实际运行验证**后确认，请勿在部署时踩坑：

### 6.1 设备心跳必然失败（`cloudfunctions/device/index.js`）

`device` 云函数在进入 `switch` **之前**就做了登录校验：

```js
if (!OPENID) return { code: 401, msg: '未登录' }   // ← 第 39 行，早于 switch
```

而硬件端 `scheduler.py` 每 3 分钟通过 HTTP 调用 `device` 的 `heartbeat` 动作。设备没有微信身份，`OPENID` 必然为空，因此**心跳恒定返回 401，`lastSeenAt` 永不更新**，小程序里药盒会一直显示「离线」。

实测对比（用项目自带的 `tests/wx-server-sdk-stub.js` 复现）：

| 调用 | OPENID | 结果 |
|---|---|---|
| `device.heartbeat`（硬件端心跳） | 空 | `{"code":401,"msg":"未登录"}`，`lastSeenAt` 仍为 `null` |
| `device.heartbeat`（小程序端调用） | 有 | `{"code":0,"data":{"deviceId":"BOX-TEST01"}}` |
| `record.report`（硬件端上报） | 空 | `{"code":0, ...}` ✅ 正常 |
| `plan.listForDevice`（硬件端拉计划） | 空 | `{"code":0, ...}` ✅ 正常 |

`record` 与 `plan` 都把设备分支放在了登录校验**之前**，所以设备上报与拉计划不受影响 —— 只有 `heartbeat` 这一条路径有问题。

**修复方向**：把 `heartbeat` 分支提到登录校验之前，并像 `record.report` 一样校验 `token`。

### 6.2 其它待办

- **真实设备对接联调**尚未完成（云端 `record` 的 `report` 与 `plan` 的 `listForDevice` 已就绪可测）
- **设备鉴权是占位方案**：当前用固定 token（默认 `zhihyao-dev-token`），正式方案应为设备密钥签名验签
- **电池电量**：`_read_battery()` 目前恒返回 `None`，云端显示「未知」（中期阶段市电供电）
- **摄像头对焦**：桌面摄像头为定焦，设计工作距离 30cm 以上，放在药仓上方 10cm 会失焦。三个办法：换可调焦 USB 摄像头模块（约 ¥40）/ 拆开拧对焦环 / **改用称重方案**（HX711 + 称重传感器，约 ¥25）—— 对「还剩多少药」这个问题，称重比摄像头更可靠且不受光照影响
- **订阅消息模板**需自行申请并填入模板 ID 后才能实际推送

## 十、设计要点

- **硬件抽象层（HAL）**：业务逻辑只调用 `hal.py` 定义的接口，从不直接碰 GPIO。因此「换硬件平台」和「无元件开发」都只是换一个实现类的事。
- **开盖即算取药**：策划书设想老人按确认键，但实际使用中很多老人拿完药直接合盖、根本不会按键 —— 只认按键会导致大量误判漏服。因此确认信号同时接受**开盖**与**按键**（两者都是边沿触发：开盖后**合盖**才判定完成，避免只是掀开看一眼就被记为已服药）。
- **断网不可丢数据**：老人家里断网是常事，服药记录不能因此丢失。设备端本地判定漏服并写入队列，联网后自动补发。
- **拉取失败不清空**：`sync_plans()` 拉不到计划时沿用本地已有计划，而非清空 —— 断网时药盒必须照常工作。
- **时区统一换算**：云函数跑在 UTC，所有日期与分钟数统一换算到北京时间再比对。
- **漏服补齐不追溯**：计划创建之前就已经过去的时点不算漏服，否则「下午建一个含早上 8 点的计划」会立刻被判成漏服。

## 十一、硬件平台变更说明（重要）

立项策划书与**实际实现**的硬件方案存在代际差异，这一点直接影响多个指标，务必知悉：

| 项目 | 策划书原方案 | 实际实现 |
|---|---|---|
| 主控 | Arduino Uno R3 / ESP32 | **Orange Pi 4 Pro（全志 A733，8 核，3 TOPS NPU）** |
| 离线语音 | DFPlayer Mini MP3 模块 + TF 卡 | **espeak-ng 合成** 或预录 `voices/bay*.wav` |
| 开盖检测 | 霍尔传感器阵列 | **A3144E 霍尔开关**（数字输出） |
| 服药确认 | 大按键确认 | 霍尔开盖 + 按键 **双通道**，另加 **USB 摄像头 + OpenCV 视觉复核** |
| 远程监护 | NFC 被动读取（NTAG213） | **微信小程序 + 云开发**（NFC 尚未实现） |
| 供电 | 18650 锂电池，续航 ≥7 天 | **市电供电**（见下） |

### 11.1 续航指标已不成立

Orange Pi 4 Pro 需要 **5V/3A = 15W**，而一颗 18650（3.7V 3000mAh ≈ 11Wh）满打满算撑不到 1 小时。
策划书的「续航 ≥7 天」是按 Arduino 低功耗方案测算的，**换成这块板子后该指标不成立**，
中期阶段改为市电供电演示。选购清单中明确标注「⚠ 中期阶段不要买 18650 电池方案」。

### 11.2 A733 无用户可用 ADC

Orange Pi 4 Pro 的 A733 芯片**没有对用户开放的 ADC**，因此模拟输出类传感器（模拟霍尔、电位器、光敏电阻）不可用。
选型一律认准「**数字输出**」，否则需外挂 ADS1115 这类 I2C ADC。本项目选用的 A3144E 即为数字输出，不受影响。

### 11.3 元器件采购与预算

- **已有设备**（不计入清单）：Orange Pi 4 Pro 开发板 ×1、USB 摄像头 ×1
- **必买部分合计 ¥375 ~ 765**：电源与散热 ¥100 / 提醒链路（按键、蜂鸣器、LED、喇叭）¥33 / 开盖检测（A3144E、钕磁铁）¥19 / 电路基础件（面包板、杜邦线）¥39 / 差异化亮点件（PN532、NTAG215、摄像头支架、演示药片）¥87 / 外壳与结构 ¥97~487
- **立项预算上限 ¥1000**（BOM 必买合计随 3D 打印外壳成本浮动）
- 元器件采购清单：`银发守护智药云联-元器件采购清单.docx`

> 策划书中「原型成本 <100 元」与「原型机材料成本 748 元以内」两处数字互相矛盾，
> 预算表合计亦存在笔误。**建议只引用「立项预算 1000 元封顶」与「量产 BOM 80–120 元」。**

### 11.4 其它已识别的技术风险

- **PN532 NFC 模块是最高风险件**：拨码开关必须拨到 I2C，VCC 必须 3.3V（接 5V 会烧毁）。
  降级预案：药盒屏幕显示二维码，子女扫码读取。
- **NFC 标签从 NTAG213 改为 NTAG215**：213 仅 144 字节，存 7 天服药记录余量不足；215 为 504 字节。
- **3D 打印成本高于策划书预估**（预估 ¥60/套，实际可能 ¥150~450/套），首选校内实验室打印机。
- **电源是第一优先级**：PD 快充头在 5V 档只给 2A 时会掉压重启，故障现象隐蔽、不易定位。
